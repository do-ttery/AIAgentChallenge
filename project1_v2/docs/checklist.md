# 작업 분해 체크리스트

> 원칙: 한 항목 = AI에게 한 번에 시킬 수 있는 크기 = 내가 10분 안에 검증할 수 있는 크기
> 순서 기준: 각 항목은 자기가 쓸 입력이 이미 만들어져 있어야 한다

## 2주차 — 기능 1: 안개 지도

### 데이터 결 (모든 것의 입력)
- [ ] JSONL 한 파일에서 AI의 파일 작업(경로·시각·도구) 목록 추출 함수
      → 검증: 내 ExamCast 로그 넣고 출력이 실제 작업 내역과 일치하는지 눈으로 확인
- [ ] 프로젝트 폴더 경로 → 해당하는 ~/.claude/projects 로그 폴더 찾기
      → 검증: 내 레포 경로 넣으면 맞는 폴더가 나오나
- [ ] git log에서 파일별 커밋 이력(누가·언제) 뽑기
      → 검증: git log 명령 결과와 대조
- [ ] 안개 판정 함수: "AI가 썼고 + 이후 내가 수정 안 함" (입력: 위 둘 → 출력: 파일별 안개 여부)
      → 검증: 내가 손댄 파일 3개, 안 댄 파일 3개 골라서 판정이 맞나
      → 판정 규칙(MVP): 이진 판정 — 직접 수정(git) 또는 탐험 통과(앱 기록) 중 하나면 밝음
- [ ] 파일 목록 → 폴더(모듈) 단위로 묶고 모듈별 안개 비율 계산
      → 검증: 수작업 계산과 일치하나

### 백엔드
- [ ] 스캔 API: 경로를 받아 스캔 실행하는 엔드포인트 1개
      → 검증: curl로 내 레포 경로 보내면 분석 결과 JSON이 오는지

### 화면 결 (API 연결 전까지는 가짜 데이터로 병렬 작업 가능)
- [ ] 모듈 타일 컴포넌트: 모듈명 + 안개 비율을 받아 타일 하나 그리기
      → 검증: 가짜 데이터 {"auth": 0.7} 넣고 타일 렌더 확인
- [ ] 타일 색칠 규칙: 안개 비율에 따라 밝음/안개 스타일 구분
      → 검증: 0% / 50% / 100% 세 가지 가짜 데이터로 색 확인
- [ ] 타일 그리드: 모듈 목록 받아 타일 나열
- [ ] 상단 장악률 컴포넌트 (전체 비율 숫자 + 게이지)
- [ ] 타일 클릭 → 그 모듈의 파일 목록 (어떤 파일이 안개인지)
- [ ] API 연결: 백엔드 스캔 결과(JSON) 받아서 위 컴포넌트들에 공급

### 온보딩
- [ ] 시작 화면: 폴더 경로 선택 UI + 선택값 저장
      → 검증: 경로 고르면 화면에 표시되는지
- [ ] 스캔 중 화면: 로딩 표시 (분석한 커밋 수·세션 수 카운트)
      → 검증: 일부러 지연 넣고 로딩이 보이는지
- [ ] 빈 상태 분기: 세션 로그가 없는 폴더면 안내 화면으로
      → 검증: Claude Code 안 쓴 아무 폴더나 넣어보기
- [ ] 스캔 완료 → 지도 화면 전환
      → 검증: 폴더 선택부터 지도까지 클릭만으로 도달하는지

**주말 마일스톤: 내 레포의 첫 안개 지도를 본다 (도그푸딩 시작)**

## 3주차 — 기능 2: 탐험 세션

### 설정 (LLM 호출 직전에 필요)
- [ ] API 키 입력 + 로컬 저장
      → 검증: 키 넣고 앱 재시작해도 유지되는지

### 데이터 결
- [ ] 코드 조각 추출: 파일 경로 → 탐험할 코드 텍스트 가져오기
      → 검증: 파일 지정하면 올바른 코드가 나오나
- [ ] LLM 요약 호출: 코드 조각 → "뭘 하는 코드인지 · 왜 이런 구조인지" 요약
      → 검증: 내가 이미 아는 파일 넣고 요약이 정확한지 판단
- [ ] LLM 퀴즈 생성: 코드 조각 → 객관식 1~2문항 JSON(질문·보기·정답·해설)
      → 검증: JSON이 파싱되고, 정답이 실제로 맞는지 직접 풀어보기

### 화면 결
- [ ] 탐험 화면: 파일명 + 코드 스니펫 + 요약 표시 (순서: 요약 먼저 → 퀴즈. 처음 보는 코드라 떠올릴 기억이 없으므로)
- [ ] 퀴즈 컴포넌트: 보기 선택 → 정답 판정
- [ ] 오답 분기: 해설 표시 + 재도전 / 정답 분기: 한 줄 리마인드
- [ ] 걷힘 연출: 통과 시 안개 해제 애니메이션 + 장악률 변화

### 연결 결
- [ ] 탐험 기록 저장: {파일, 통과 시각, 퀴즈 결과} 로컬 JSON 저장 (md 아님 — 판정 함수가 조회해야 하므로 구조화 필요)
      → 검증: 통과 후 JSON 열어 기록 확인
- [ ] 판정 반영: "탐험 통과 파일 = 밝음"을 안개 판정 함수에 추가
      → 검증: 통과한 파일이 지도에서 밝아지나
- [ ] 지도 복귀 시 최신 상태로 갱신

**주말 마일스톤: 탐험으로 안개 1칸을 실제로 걷는다 + 동료 1명 테스트**

## 4주차 — 완성도·발표

- [ ] 버그픽스 및 전체 흐름 다듬기
- [ ] 동료 2~3명 레포 테스트, 첫 지도 반응 기록
- [ ] 도그푸딩 지표 정리 (감지 안개량, 탐험 횟수, 장악률 추이)
- [ ] 데모 시나리오 작성 + 발표 자료
- [ ] (스트레치 — 화요일까지 여유 있을 때만) 브리핑 배너: 앱 실행 시 "지난 세션 이후 안개 +N"

**주말 마일스톤: 데모 데이**
