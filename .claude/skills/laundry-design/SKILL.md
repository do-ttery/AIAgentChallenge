# 무인빨래방 AI 점장 — 디자인 제작 스킬

이 스킬은 프로젝트의 **톤(색·폰트·간격·카드·문구)**을 규칙으로 고정한다.
화면을 새로 만들 때 이 규칙을 적용하고, 다 만든 뒤 §6 체크리스트로 검증한다.

## 1. 언제 쓰나
- 고객/사장님 화면, 컴포넌트, HTML 프로토타입을 만들 때
- 이미 만든 디자인이 규칙·의도에 맞는지 확인할 때
- 새 색·간격 등을 정해야 할 때 (임의로 정하지 말고 이 규칙 안에서)

## 2. 색 토큰 (CSS 변수)

```css
:root {
  --ink: #1f2937;          /* 본문 텍스트 */
  --sub: #6b7280;          /* 보조 텍스트 */
  --line: #e5e7eb;         /* 테두리 */
  --bg: #f3f4f6;           /* 페이지 배경 */
  --accent: #6366f1;       /* 주 강조 (버튼, 진행바) */
  --accent-dark: #4338ca;  /* 강조 텍스트 */
  --accent-soft: #eef2ff;  /* 강조 배경 */
  --ok: #059669;           /* 완료·정상 */
  --ok-soft: #ecfdf5;
  --warn: #d97706;         /* 방치·확인 필요 */
  --warn-soft: #fff7ed;
}
```

- **기계 상태별 색 고정**: 세탁 중 = `accent` / 수거 완료 = `ok` / 방치·확인 필요 = `warn` / 대기 = 회색(`--bg` 배경 + `--sub` 텍스트)
- **빨강 계열 금지** — 고객을 비난하는 인상을 주지 않는다. 최고 경고 단계도 `warn`(주황)까지.

## 3. 타이포 · 형태

- 폰트: `'Pretendard', 'Apple SD Gothic Neo', 'Noto Sans KR', sans-serif`, 본문 line-height 1.55
- 크기: 페이지 제목 20~24px(800) / 카드 제목 18~21px(800) / 본문 13.5~15px / 보조 12~13px
- 라운드: 카드 12~16px, 버튼 12px, 배지·칩 999px(완전 원형)
- 그림자: 카드에만 약하게 `0 4px 20px rgba(0,0,0,.05)`

## 4. 레이아웃

- **고객 화면**(QR 랜딩, 진행 중): 센터 카드형, 카드 `max-width: 460px`. 모바일 브라우저 기본 가정
- **사장님 화면**(대시보드): 사이드바(200px) + 메인. 상단 요약 지표 3개(stat) → 기기 카드 그리드 → 처리 내역 피드 순서
- URL: 고객 `/m/:machineId`, `/m/:machineId/status` · 사장님 `/owner/...`

## 5. 도메인 UI 규칙 (반드시 지킬 것)

1. **예측 시각은 점이 아니라 범위로**: "18:49" 단독 금지 → "18:49 종료 예상 · 범위 18:45~18:55". 예측이 갱신되면 범위가 좁아지는 방향으로
2. **자동 처리 vs 사장님 개입을 색으로 구분**: 에이전트 자동 해결 = `ok`색 / 확인 필요 = `warn`색
3. **방치 표시는 사실만**: "방치 32분 · 2차 알림 발송됨"처럼 상태+조치를 담백하게. 고객 비난 톤 금지
4. **고객 화면엔 항상 다음에 일어날 일을 예고**: "탈수가 감지되면 출발 알림을 보내드려요"
5. **사용자 입력은 항상 선택 사항**으로 표현 ("안 골라도 돼요")

## 6. 알림 문구 톤

- 출발 알림: 친절+행동 유도 — "10분 후 종료 예정이에요. 지금 출발하세요!"
- 완료 알림: 짧고 명확 — "세탁이 끝났어요. 세탁기 3번"
- 1차 수거 넛지(종료 30분): 부드럽게 — "세탁물이 기다리고 있어요"
- 2차 넛지(1시간~): 정중하지만 단호 — 매장 정책 안내 포함
- 사장님 보고: 요약형, 수치 먼저 — "방치 3건 발생 → 3건 자동 해결"

## 7. 화면 만드는 절차

1. **적용**: §2~4를 먼저 세팅(토큰을 `:root`에, 폰트·라운드 지정)
2. **껍데기**: 기능 없이 보이는 것만 — 해당 화면의 핵심 요소를 배치
3. **도메인 규칙 반영**: §5·§6을 화면에 실제로 적용(범위 표기, 색 구분, 예고 문구)
4. **다듬기**: §8 체크리스트로 스스로 점검 → 어긋난 부분 수정
5. 여기 없는 결정이 필요하면 **임의로 정하지 말고 질문**한다

## 8. 검증 체크리스트 (완성 후 확인)

- [ ] 상태 색이 규칙대로인가? (세탁 중=accent / 완료=ok / 방치=warn / 대기=회색)
- [ ] **빨강을 쓰지 않았는가?**
- [ ] 예측 시각을 **범위**로 표기했는가?
- [ ] 자동 처리와 개입 필요가 **색으로 구분**되는가?
- [ ] 방치 표시가 비난 없이 **사실+조치**로만 되어 있는가?
- [ ] 고객 화면에 **다음 일어날 일 예고**가 있는가?
- [ ] 폰트·크기·라운드·그림자가 §3 범위 안인가?
- [ ] 레이아웃이 §4(고객 센터카드 / 사장님 사이드바)를 따르는가?

## 9. 피드백으로 이 스킬 고치기

디자인 결과가 마음에 안 들면 코드만 고치지 말고 **이 스킬 파일에 규칙을 추가/수정**한다.
(예: "카드 배경을 더 따뜻하게" → §2에 `--card-bg` 토큰 추가 후 반영)
그래야 다음 화면부터 같은 품질로 재사용된다.
