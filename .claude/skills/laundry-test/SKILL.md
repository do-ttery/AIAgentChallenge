# TDD Flow (server 순수 함수용)

## 언제 쓰나

- 대상: `server/services/`의 순수 함수 — 검증·계산·판정·변환. 입력과 기대 출력이 CLAUDE.md 스펙(전력 임계값·eta 공식·방치 시간 등)으로 이미 정해져 있는 것
- 대상 아님: DB 접근이 섞인 함수(`stateMachine.js`의 `handleWatt`류), 화면(UI) — 눈으로 보는 게 더 빠르다

## 절차

### 1. 스펙과 시나리오

코드를 쓰기 전에 입력→기대 출력 표를 먼저 만든다. 근거는 CLAUDE.md 상수·전이표뿐 — 스펙에 없는 임계값·판단 기준을 새로 지어내지 않는다(CLAUDE.md "AI는 임의 판단하지 않는다"). 애매하면 사용자에게 확인한다.

정상 케이스뿐 아니라 경계값(자정 롤오버, 임계값 정확히 그 값, 빈 입력 등)을 최소 1개 포함한다.

### 2. Red

1의 표를 `<대상>.test.js`로 그대로 옮긴다. 대상 파일이 아직 없으면:
- 먼저 실행해서 **import 에러**(테스트가 실행조차 안 됨)를 확인한다
- 스텁(항상 같은 값을 리턴하는 빈 구현)을 만들고 다시 실행해 **진짜 red**(테스트는 돌지만 assertion 실패)를 확인한다

`npx vitest run <파일명>` 실행 결과를 그대로 사용자에게 보여준다 — red를 실제로 봐야 다음 단계로 넘어갈 수 있다.

### 3. Green

테스트를 통과시키는 최소 구현을 쓴다. 표에 없는 케이스까지 미리 처리하지 않는다. `npx vitest run <파일명>`으로 초록을 확인한다.

### 4. Refactor

기존 코드에 같은 로직이 중복돼 있으면(예: 라우트 안에 인라인으로 있던 계산) 새로 만든 함수를 import하도록 정리하고, 중복을 지운다. 정리 후 반드시 테스트를 다시 돌려 여전히 초록인지 확인한다.

## 완료 기준

- [ ] 시나리오 표에 경계값이 최소 1개 있다
- [ ] red를 실제로 실행해서 확인했다 (건너뛰지 않았다)
- [ ] green도 실제로 실행해서 확인했다
- [ ] 구현이 표에 없는 케이스까지 앞서 처리하지 않았다 (과설계 금지)
- [ ] 리팩토링 후 테스트를 다시 돌렸다
- [ ] 새 상수·임계값을 임의로 짓지 않았다 — 전부 CLAUDE.md 또는 `services/constants.js` 근거
